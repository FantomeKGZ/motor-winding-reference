# План объединения внешнего сайта и CoilMaster/ESP32

Статус актуализирован 2026-08-07. Подробное описание фактически реализованных функций находится в `docs/CURRENT_STATUS.md`.

## Этап 1 — сохранить справочник — В ОСНОВНОМ ВЫПОЛНЕНО

Выполнено:

- исходники `sourse/` не изменяются;
- desktop и mobile используют собственные оригинальные главные страницы;
- сохранены таблицы, технический текст, изображения и ссылки;
- старый верхний баннер убран только из новой рабочей оболочки;
- обычные HTML-страницы открываются внутри `page.html` без изменения исходников;
- добавлена ссылка на оригинальную страницу для проверки;
- изображения и схемы не удаляются и не объединяются автоматически.

Остаётся:

- провести финальный визуальный проход по репрезентативному набору старых страниц и сравнить их с оригиналом.

## Этап 2 — инвентаризация — ВЫПОЛНЕНО ДЛЯ ТЕКУЩЕГО АРХИВА

Реализованы инструменты:

- `tools/build_scheme_index.py` — проверка локальных ссылок;
- `tools/build_home_tables.py` — извлечение структуры главных таблиц;
- `tools/build_image_inventory.py` — SHA-256, размеры и использование изображений;
- `tools/build_page_inventory.py` — аудит HTML-страниц, стилей, текста, ссылок и изображений;
- `tools/build_search_index.py` — полнотекстовый поисковый индекс.

Зафиксировано:

- 1856 HTML-страниц в каждой версии;
- 5522 изображения в каждой версии;
- битых ссылок главной таблицы не найдено;
- автоматическая дедупликация запрещена.

GitHub Actions автоматически повторяет эти проверки.

## Этап 3 — внешний Integration Layer — ЧАСТИЧНО ВЫПОЛНЕНО

Выполнено на стороне внешнего сайта:

- создан `site/shared/js/esp32-client.js`;
- поддерживаются режимы `off`, `mock`, `live`;
- создан read-only контракт `GET /api/context`;
- есть таймаут и отказоустойчивость;
- ESP32 можно настраивать из боковой панели;
- отображаются статус соединения и текущий двигатель;
- при недоступности ESP32 справочник продолжает работать автономно.

Не выполнено:

- endpoint `/api/context` ещё должен быть реализован в проекте прошивки ESP32;
- склад, история, журнал событий и остальные сущности ESP32 пока не подключены.

## Этап 4 — сопоставление двигателя со схемой — БАЗОВАЯ ВЕРСИЯ ВЫПОЛНЕНА

Уже работает:

- `motor_id` не используется как единственный ключ;
- после получения контекста ESP32 внешний сайт читает реальную оригинальную таблицу;
- выполняется сопоставление по `slots + rpm`;
- подходящая строка и ячейка подсвечиваются;
- показывается список кандидатов;
- конкретная схема автоматически не выбирается;
- есть положительные и отрицательный mock-тесты.

Следующее развитие:

- учитывать `poles`;
- учитывать `winding_type`;
- учитывать `parallel_branches`;
- учитывать `connection`;
- учитывать специальные признаки многоскоростных и нестандартных обмоток;
- показывать различия между оставшимися кандидатами.

После инвентаризации самостоятельным схемам можно присвоить стабильный `scheme_id`.

## Этап 5 — глубокие ссылки — ПОДГОТОВЛЕНА ОСНОВА

Уже существует единая маршрутизация страниц через:

`page.html?src=...`

Также каждая открытая схема формирует `CoilMasterSchemeContext` с параметрами и путём исходной страницы.

Дальше необходимо реализовать стабильные переходы:

- ESP32 → внешняя расширенная карточка/схема;
- внешний сайт → локальная карточка проекта ESP32;
- переход по `scheme_id` после появления реестра схем.

Физическое имя старого HTML-файла допускается как внутренний legacy-маршрут, но не должно становиться долговременным публичным идентификатором интеграции.

## Этап 6 — команды записи — НЕ НАЧАТ

Только после стабилизации read-only интеграции:

- подтверждённые изменения проекта;
- выбор/сохранение `scheme_id`;
- операции со складом;
- передача подготовленного задания.

Команды управления станком не смешивать с обычной навигацией сайта. Любые операции, способные изменить данные или состояние оборудования, должны иметь отдельный API, валидацию и явное подтверждение пользователя.

## Дополнительные функции внешнего справочника — ВЫПОЛНЕНЫ

Помимо основной дорожной карты уже реализованы:

- быстрый поиск `пазы + обороты` по исходной таблице;
- полнотекстовый поиск по старым страницам;
- фильтры результатов по типу материала;
- история последних открытых страниц;
- избранные страницы;
- сохранение позиции прокрутки при возврате;
- кнопка `Наверх`;
- компактный блок параметров схемы;
- стандартный `CoilMasterSchemeContext` для будущей интеграции.
