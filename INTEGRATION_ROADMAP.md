# План объединения внешнего сайта и CoilMaster/ESP32

## Этап 1 — сохранить справочник

- не изменять исходники `sourse/`;
- воспроизвести привычные главные страницы;
- проверить все ссылки, тексты и изображения;
- не удалять и не объединять схемы автоматически.

## Этап 2 — инвентаризация

- построить реестр HTML-страниц;
- построить реестр изображений;
- определить, где используется каждое изображение;
- сравнивать потенциальные дубликаты по байтам/хэшу и отдельно по визуальным отличиям;
- любое отличающееся изображение считать отдельной схемой, пока не доказано обратное.

## Этап 3 — внешний Integration Layer

- добавить клиент API ESP32;
- начать с режима только чтения;
- показывать состояние ESP32, текущий двигатель, склад и историю;
- при недоступности ESP32 внешний справочник должен продолжать работать автономно.

## Этап 4 — сопоставление двигателя со схемой

- не использовать `motor_id` как единственный ключ к схеме;
- передавать параметры двигателя/обмотки;
- внешний сайт подбирает подходящие схемы;
- при неоднозначности показывать несколько вариантов для выбора мастером;
- выбранную схему в будущем можно сохранять как `scheme_id` в проекте ESP32.

## Этап 5 — глубокие ссылки

Предусмотреть переходы:

- ESP32 → внешняя расширенная карточка/схема;
- внешний сайт → локальная карточка проекта ESP32;
- ссылки должны использовать стабильные параметры/идентификаторы, а не физические имена HTML-файлов там, где это возможно.

## Этап 6 — команды записи

Только после стабилизации чтения:

- подтверждённые изменения проекта;
- выбор/сохранение схемы;
- операции со складом;
- передача подготовленного задания.

Команды управления станком не смешивать с обычной навигацией сайта.
