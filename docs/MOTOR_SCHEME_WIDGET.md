# Виджет «Обмотка и схемы» в карточке двигателя

## Назначение

`site/shared/js/motor-scheme-widget.js` — компактный компонент для карточки двигателя CoilMaster. Он не хранит изображения и не записывает данные в ESP32. Компонент получает уже сохранённую привязку двигателя к каталогу и показывает её пользователю.

Основная модель:

`motor record -> scheme_id + connection_id -> scheme catalog -> preview + navigation`.

## Отображение

Если схема привязана, виджет показывает:

- стабильный `scheme_id`;
- изображение выбранной схемы укладки;
- описание варианта;
- шаг `y`, если известен;
- допустимые параллельные ветви `a`;
- типы обмотки;
- количество всех схем подключения для выбранной укладки;
- до двух компактных превью схем подключения;
- отдельную отметку выбранного для данного двигателя `connection_id`;
- кнопку открытия полной схемы укладки;
- кнопку `Все схемы подключения (N)`, если вариантов больше двух;
- `Изменить привязку`;
- `Удалить привязку`.

Если схема не привязана, показывается нейтральное состояние `Схема обмотки к этому двигателю пока не привязана` и кнопка `Выбрать схему`.

## Почему показываются максимум два подключения

Каталог подтвердил, что одна укладка может иметь до 8 уникальных страниц подключения. Поэтому карточка двигателя не должна пытаться вывести их все одновременно. По умолчанию показываются два первых компактных варианта, а остальные открываются отдельным действием.

## Связь со Scheme Picker

Метод `CoilMasterMotorSchemeWidget.bindPicker(...)` использует `CoilMasterSchemePicker` для изменения привязки. Это позволяет использовать один и тот же механизм:

- при создании двигателя;
- при редактировании существующего двигателя;
- при замене схемы;
- при замене выбранного подключения.

Сам виджет не вызывает Motor Database API. После подтверждения Scheme Picker он вызывает callback `onBindingChange`, а внешний редактор двигателя решает, сохранять ли изменение.

## Состояния

Компонент должен корректно работать в следующих случаях:

1. Привязки нет — предложить выбрать схему.
2. `scheme_id` есть и схема найдена — показать полную карточку.
3. Схема есть, но нет отдельных `connection_options` — показать укладку и объяснить отсутствие отдельной схемы подключения.
4. Подключений несколько — показать два preview и кнопку со всем количеством.
5. `connection_id` выбран — отметить его как фактически выбранное подключение данного двигателя.
6. Изображение недоступно — текстовые данные и действия остаются доступны.

## Интерфейс API компонента

Минимальное использование:

```js
CoilMasterMotorSchemeWidget.render(container, {
  binding,
  scheme,
  connection,
  onEdit(detail) {},
  onRemove(detail) {},
  onShowConnections(detail) {}
});
```

Вариант с автоматическим запуском Scheme Picker:

```js
CoilMasterMotorSchemeWidget.bindPicker(container, {
  motor,
  binding,
  scheme,
  connection,
  candidates,
  onBindingChange(selection) {},
  onRemove(detail) {},
  onShowConnections(detail) {}
});
```

## Что хранится в Motor Database

В базе двигателя рекомендуется сохранять только компактную ссылку:

```json
{
  "winding_reference": {
    "scheme_id": "CM-SCH-...",
    "connection_id": "CM-CON-...",
    "catalog_version": 3
  }
}
```

Не следует дублировать в записи двигателя:

- исходный HTML;
- большие изображения;
- весь массив допустимых подключений;
- текстовые описания из справочника.

Эти данные принадлежат каталогу и могут отображаться по идентификаторам.

## Важное правило

`connection_id` означает выбранную для конкретной карточки двигателя схему подключения. При этом каталог продолжает хранить все допустимые варианты подключения выбранной схемы укладки. Выбор одного варианта в карточке не удаляет и не скрывает остальные из справочника.
