# Контроль качества каталога схем

Статус: активная часть внешнего сайта `motor-winding-reference`.

## Цель

Каталог используется в Scheme Picker и в будущем будет связан с карточкой двигателя через стабильные `CM-SCH-*` и `CM-CON-*`. Поэтому ошибка в производных данных опаснее отсутствующего превью: неверная картинка может привести мастера к неправильной укладке или подключению.

Исходный справочник в `sourse/` остаётся неизменяемым. Все проверки работают только с производными JSON и чтением старого HTML.

## Жёсткие проверки

### Изображения укладки

`validate_scheme_catalog_images.py` запрещает служебным marker/icon изображениям становиться основным `scheme.image`.

### Изображения подключения

`validate_connection_option_images.py` проверяет, что каждый `scope: "image"`:

- имеет реальную страницу `ss*.html`;
- имеет существующий файл картинки;
- эта страница действительно ссылается на картинку;
- картинка не является служебным значком;
- `connection_id` соответствует правилу `page + image + type`.

`scope: "page"` не имеет права притворяться конкретной картинкой.

### Известные реальные случаи

`validate_known_catalog_cases.py` защищает несколько хорошо понятных примеров из оригинального справочника. В частности, для `36 пазов / 3000 об/мин` проверяется настоящая двухслойная схема `y=15` и страница `ss2k3000a2.html`.

Для `ss2k3000a2.html` должны различаться:

- комбинированная картинка `звезда + треугольник` как один `star_delta`;
- отдельная картинка `star`;
- отдельная картинка `delta`.

Комбинированная картинка не должна одновременно создавать ложные отдельные `star` и `delta`.

### Общая структура

`validate_scheme_catalog.py` проверяет стабильные ID, уникальность, счётчики, битые страницы и соответствие desktop/mobile.

## Информационные аудиты

### Page-scoped подключения

`audit_page_scoped_connections.py` показывает варианты, где страница подключения известна, но конкретное изображение пока не доказано.

Это допустимое состояние. Правило проекта:

> Нет превью лучше, чем неверное превью.

### Шаблоны неоднозначных страниц

`audit_connection_page_templates.py` группирует реальные `ss*.html` по структуре и ищет подписи, рядом с которыми находится ровно одна реальная картинка. Эти данные нужны для будущего улучшения общих правил распознавания.

Аудит сам ничего не переводит из `scope: "page"` в `scope: "image"`.

## Runtime fallback внешнего сайта

`site/shared/js/scheme-catalog-client.js` имеет резервный режим на случай отсутствия готового JSON-каталога.

В нём применяются те же консервативные правила:

- служебные `met*`, `marker`, `icon`, `recommend` и `images/sovmob/*` не становятся схемами;
- комбинированная подпись звезда/треугольник классифицируется как `star_delta`;
- стабильные ID строятся тем же SHA-1 правилом.

Runtime fallback не заменяет основной каталог и используется только как резервный путь.

## Требование для будущего ChatGPT/ИИ

При улучшении распознавания нельзя добавлять правило вида «первая картинка на странице является нужной» или массово назначать картинки по имени файла без подтверждения старым HTML.

Правильный порядок:

1. получить статистику аудита;
2. выбрать частый HTML-шаблон;
3. доказать связь подписи и картинки на нескольких реальных страницах;
4. добавить общее правило;
5. прогнать все валидаторы и known-case regression;
6. убедиться, что desktop/mobile остаются семантически одинаковыми.

Работа этого документа относится только к внешнему сайту. Код ESP32 не изменяется до отдельного этапа по `ESP32_CONNECTION_HANDOFF.md`.
