# Сопоставление данных двигателя со схемами обмотки

## Основной принцип

Схема укладки и схема соединения — самостоятельные справочные сущности. Они не принадлежат одной конкретной модели двигателя и могут подходить нескольким двигателям.

Поэтому связь строится так:

`рабочие данные ESP32 → параметры обмотки → поиск кандидатов во внешнем справочнике → выбранная схема`

## Текущее состояние алгоритма

Рабочий подбор разделён на четыре ступени.

### Ступень 1 — главная таблица

`site/shared/js/esp32-scheme-matcher.js`:

1. читает реальные ссылки из загруженной оригинальной главной таблицы;
2. определяет число пазов из строки таблицы;
3. читает обороты из атрибута `title` исходной ссылки;
4. при наличии читает `q` из того же `title`;
5. требует точное совпадение `slots + rpm`;
6. если ESP32 передала `q` и оно указано в ссылке, требует совпадение `q`.

Важно: обороты берутся именно из метаданных исходной ссылки. В оригинальной таблице внутри `<a>` обычно находится только изображение, поэтому `textContent` ссылки не является надёжным источником оборотов.

### Ступень 2 — проверка самой страницы-кандидата

После первичного отбора сайт загружает только оставшиеся страницы-кандидаты из `sourse/`, декодирует их из Windows-1251 и извлекает безопасные признаки без изменения исходника.

Сейчас извлекаются:

- `2p` / число полюсов из таблицы параметров;
- `q` из таблицы параметров;
- наличие описаний однослойной и двухслойной обмотки;
- наличие цепной обмотки и варианта «вразвалку»;
- признаки расширенной и сплошной фазной зоны;
- перечисленные на странице возможные значения параллельных ветвей `a`;
- ссылки на отдельные страницы схем соединений как справочная метаинформация.

Если ESP32 передала `poles`, `winding_type` или `parallel_branches`, эти значения используются как дополнительные фильтры. Если параметр на странице не удалось надёжно извлечь, сайт не выдумывает его и не исключает кандидата только из-за отсутствия данных.

Результаты разбора страниц кешируются в памяти браузера на время текущего открытия сайта, поэтому одна и та же страница не загружается повторно при каждом сравнении.

### Ступень 3 — отдельные рисунки укладки внутри страницы

Модуль `site/shared/js/scheme-variant-navigation.js` получает уже отобранные страницы и разбирает каждое отдельное описание вида «Схема укладки …» вместе со следующим рисунком.

Для варианта фиксируются:

- путь исходной HTML-страницы;
- путь изображения конкретной укладки;
- полный исходный текст описания;
- раздел страницы, в котором находится вариант;
- типы обмотки, которые можно безопасно распознать из текста;
- шаг `y`, если он явно записан в описании;
- допустимые параллельные ветви `a`;
- ссылки на страницы схем соединения `ss*.html`;
- текстовые подсказки значков.

Если ESP32 передала `winding_type`, `parallel_branches` или `winding_pitch`, модуль может дополнительно сократить список уже на уровне отдельных рисунков.

Из списка можно открыть конкретный вариант. В URL передаётся параметр `img`, а на `page.html` тот же модуль после загрузки старой страницы находит нужный рисунок, прокручивает страницу прямо к нему и выделяет соответствующий блок. Оригинальная структура страницы при этом не меняется.

### Ступень 4 — проверка страницы схемы соединения

Теперь ссылки `ss*.html`, найденные у конкретного варианта укладки, не считаются просто строковыми ссылками. Модуль загружает только связанные страницы схем соединений и разбирает их содержимое.

Из них определяются явно описанные варианты соединения:

- `star` — звезда;
- `delta` — треугольник;
- наличие обоих вариантов на одной странице.

Например, страница `ss2k3000a2.html` содержит отдельные изображения соединения в звезду и в треугольник при `a=2`. Если ESP32 передаёт `connection: "Y"`, `connection: "star"`, `connection: "delta"` или эквивалентную русскую запись, список рисунков дополнительно фильтруется по реально найденным данным страницы соединения.

Для найденного варианта в интерфейсе появляется отдельная ссылка «Открыть схему соединения». Если для нужного типа соединения удалось определить конкретное изображение, переход открывает `page.html` сразу возле этого рисунка через тот же параметр `img`.

Разбор страниц соединений также кешируется в памяти браузера. ESP32 в этой работе не участвует и дополнительной нагрузки не получает.

Это остаётся навигационным сопоставлением. Даже один оставшийся результат не считается автоматически подтверждённой электрической схемой без проверки мастером.

## Входные параметры

Минимально необходимый набор:

- `slots` — число пазов;
- `rpm` — обороты/скоростная группа.

Поддерживаемые дополнительные критерии:

- `q` — число пазов на полюс и фазу;
- `poles` — число полюсов / `2p`;
- `winding_type` — тип обмотки;
- `parallel_branches` — число параллельных ветвей;
- `winding_pitch` — явно известный шаг `y` конкретного варианта;
- `connection` — звезда/треугольник, если этот параметр известен ESP32.

Параметры для следующих ступеней:

- `phases` — число фаз;
- дополнительные признаки для специальных, переключаемых и многоскоростных машин.

Сайт не должен выводить отсутствующие технические параметры из косвенных чисел имени файла, если это не зафиксировано отдельным надёжным правилом.

## Многоступенчатая схема поиска

Текущая последовательность:

1. обязательная группа `slots + rpm`;
2. `q`, если доступно с обеих сторон;
3. чтение страницы-кандидата;
4. проверка `2p`;
5. проверка типа обмотки;
6. проверка возможного числа параллельных ветвей;
7. разбор отдельных вариантов укладки;
8. дополнительная проверка `winding_type`, `a` и `winding_pitch` уже для конкретного рисунка;
9. загрузка только связанных `ss*.html`;
10. проверка `connection` по реальному содержимому страницы соединений;
11. показ оставшихся вариантов с быстрым переходом и к укладке, и к схеме соединения.

Следующий технический этап — классифицировать специальные схемы соединений и многоскоростные варианты, где простой пары «звезда/треугольник» недостаточно.

## Результат поиска

Поиск может вернуть:

1. одну подходящую страницу, рисунок укладки и соответствующую схему соединения — показать как наиболее конкретный кандидат, но оставить техническую проверку;
2. несколько рисунков — показать мастеру различия по `y`, типу, `a` и соединению;
3. только страницу-группу — открыть её для ручного выбора;
4. нет совпадений — сохранить обычный ручной поиск по привычной таблице.

Нельзя автоматически выбирать схему только по имени модели двигателя.

## Контрольные тесты

`site/shared/data/esp32-mock.json` содержит положительные и отрицательные случаи. Режим `?esp32test=1` проверяет ограничения `expected.min_matches` и `expected.max_matches` для уровня страниц.

Основной mock-контекст теперь содержит:

- `winding_type: "двухслойная"`;
- `parallel_branches: 2`;
- `winding_pitch: "10"`;
- `connection: "Y"`.

Это позволяет визуально проверить полный проход от группы `24 / 3000` до конкретных рисунков укладки и связанной схемы соединения в звезду. Параметр `connection` относится к четвёртой ступени и поэтому не используется как отрицательный тест уровня страниц; его проверка выполняется модулем вариантов после загрузки связанных `ss*.html`.

## Идентификатор схемы

После инвентаризации каждой самостоятельной схеме можно присвоить стабильный `scheme_id`. На первом этапе `scheme_id` живёт только во внешнем сайте. Позже выбранный идентификатор может сохраняться в записи проекта на ESP32 как ссылка, а не как копия схемы.

В качестве основы будущего `scheme_id` уже можно использовать пару `source_path + image_path`, поскольку модуль третьей ступени различает конкретные рисунки внутри одной страницы.

Для связи с электрической схемой отдельно следует хранить путь страницы соединения и путь конкретного изображения соединения, а не смешивать эти сущности в один идентификатор.

## Правила для изображений

- оригинальные изображения не удалять;
- одинаковое имя файла не доказывает одинаковое содержание;
- одинаковый размер не доказывает одинаковое содержание;
- точное совпадение хэша доказывает одинаковые байты, но прежде чем объединять ссылки, всё равно проверить контекст использования;
- изображения с любым графическим отличием считать разными;
- в финальном реестре хранить список страниц, использующих изображение.

## Совместимость со старым интерфейсом

Новый подбор схем является дополнительной возможностью. Оригинальная таблица «число пазов × обороты» и привычные переходы должны оставаться доступными независимо от работы автоматического сопоставления.
