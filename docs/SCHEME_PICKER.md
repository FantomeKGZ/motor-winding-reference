# Scheme Picker — выбор схемы для карточки двигателя

## Назначение

`site/shared/js/scheme-picker.js` — переиспользуемый компонент выбора схемы укладки и конкретной схемы подключения.

Он предназначен для двух одинаковых сценариев:

1. создание нового двигателя;
2. редактирование существующей карточки двигателя.

Компонент не пишет данные в ESP32 сам. Он только возвращает выбранную привязку вызывающему коду.

## Публичный API

```js
window.CoilMasterSchemePicker.open({
  motor,
  candidates,
  currentBinding,
  onSelect
});
```

`motor` — параметры двигателя для заголовка и дальнейшей фильтрации.

`candidates` — список уже подходящих схем. В рабочем варианте он должен приходить из `scheme-catalog.json` или из существующего слоя сопоставления.

`currentBinding` — текущая привязка при редактировании:

```json
{
  "scheme_id": "CM-SCH-...",
  "connection_id": "CM-CON-..."
}
```

`onSelect` получает выбранные схему, подключение и компактный объект `binding`.

## Результат выбора

Компонент формирует минимальную привязку:

```json
{
  "scheme_id": "CM-SCH-...",
  "connection_id": "CM-CON-...",
  "catalog_version": 3
}
```

Путь старого HTML и изображения не являются основным ключом карточки двигателя. Они остаются внутри каталога.

## Событие

После подтверждения публикуется:

`coilmaster:scheme-binding-selected`

В `event.detail` находятся:

- `binding`;
- выбранная запись схемы;
- выбранный вариант подключения;
- исходный объект двигателя.

## Поведение интерфейса

В левой части показывается список подходящих схем укладки.

Для выбранной схемы отображаются:

- крупное превью укладки;
- описание;
- шаг `y`;
- значения `a`;
- тип обмотки;
- все доступные варианты подключения.

Схемы подключения показываются отдельными мини-карточками с изображением, если оно определено надёжно.

Если подключений нет, это отображается явно и не блокирует выбор самой схемы укладки.

На мобильном интерфейсе окно перестраивается в одну колонку.

## Правила сохранения

Scheme Picker сам не вызывает POST/PUT endpoint ESP32. Это намеренное разделение обязанностей.

Правильная цепочка:

`Motor Editor -> Scheme Picker -> binding -> Motor Editor validation -> ESP32 Motor API`

Таким образом, создание двигателя и редактирование используют один и тот же picker, а правила сохранения остаются в модуле базы двигателей ESP32.
