# Аудит изображений исходного справочника

Этот документ фиксирует результаты автоматической инвентаризации изображений. Исходные каталоги `sourse/desktop` и `sourse/mobile` не изменяются.

## Результат проверки

На текущем снимке справочника найдено:

- desktop: **5522** изображения;
- mobile: **5522** изображения;
- всего файлов изображений: **11044**;
- уникального байтового содержимого по SHA-256: **5521**;
- групп точных побайтовых совпадений: **5519**;
- файлов, на которые анализатор не нашёл прямой ссылки из HTML: **5710**.

Почти весь набор изображений desktop имеет побайтно идентичную копию в mobile. Это ожидаемо для двух вариантов одного справочника, но само по себе **не является разрешением на удаление или объединение файлов**.

Обнаружены две группы, содержащие по четыре одинаковых файла; остальные группы точных совпадений в основном состоят из пары desktop/mobile. Такие группы дополнительно проверяются по контексту страниц.

## Обязательная политика

1. Никакое изображение не удаляется автоматически.
2. Никакое изображение не заменяется другим только потому, что оно визуально похоже.
3. SHA-256 подтверждает только полное совпадение байтов конкретных файлов.
4. Даже точный дубликат проверяется по контексту использования перед оптимизацией финальной сборки.
5. Файл без найденной HTML-ссылки не считается ненужным: он может использоваться из CSS, JavaScript, старой страницы, относительного пути нестандартного вида либо быть резервным материалом.
6. Оригинальные изображения в `sourse/` остаются эталоном и не изменяются.

## Генерируемые отчёты

GitHub Actions создаёт:

- `site/shared/data/image-inventory.json` — полный перечень изображений, хешей и найденных ссылок;
- `site/shared/data/image-exact-duplicates.json` — только группы точных SHA-256 совпадений.

Эти JSON-файлы используются для анализа и не являются командой на очистку проекта.

## Следующий этап

Перед любой оптимизацией изображений необходимо построить инвентаризацию всех HTML-страниц: заголовок, объём текста, подключаемые CSS, inline-стили, изображения и локальные переходы. Это позволит понять контекст каждой схемы и сохранить весь накопленный технический текст старого сайта.
