# Решения по интерфейсу справочника

Актуализировано 2026-08-07. Полный перечень реализованных возможностей находится в `docs/CURRENT_STATUS.md`.

## Главный принцип

Главные страницы настольной и мобильной версий должны оставаться узнаваемыми для пользователей старого справочника. Новая оболочка добавляет удобство вокруг исходного содержимого, но не заставляет пользователя заново изучать справочник.

Сохраняются:

- центральная таблица выбора по числу пазов и оборотам;
- все данные таблицы и исходные ссылки;
- порядок основных разделов;
- технический текст старых страниц;
- изображения и схемы;
- знакомая геометрия рабочих таблиц;
- отдельные desktop и mobile входные страницы.

Осознанно убран старый верхний графический баннер на рабочих страницах: он занимал место и не содержал рабочих данных. Оригинальная страница при этом всегда остаётся доступна для проверки.

## Что уже добавлено без разрушения старой логики

- боковое меню CoilMaster на ПК;
- выдвижное меню на телефоне;
- переключение desktop/mobile;
- стартовая страница выбора интерфейса с сохранением выбора;
- быстрый поиск по оригинальной таблице;
- полнотекстовый поиск по всему справочнику;
- фильтры результатов по типу материала;
- горизонтальная прокрутка таблиц;
- закреплённый первый столбец на мобильной версии;
- открытие старых страниц внутри новой оболочки;
- кнопки `Назад`, `К таблице схем`, `Оригинальная страница`;
- кнопка `Наверх`;
- восстановление позиции главной таблицы после возврата;
- история последних страниц;
- избранное;
- компактный блок параметров схемы;
- панель ESP32 со статусом и настройкой адреса;
- подсветка подходящей группы схем после получения данных ESP32.

## Ограничения

- каталог `sourse/` является неизменяемым архивом исходников;
- новые страницы и логика создаются в `site/`;
- аналитические инструменты находятся в `tools/`;
- содержимое и авторские подписи не сокращаются автоматически;
- изображения не удаляются и не объединяются автоматически;
- технические параметры отсутствующих данных не угадываются;
- публикация материалов должна учитывать условия правообладателя исходного справочника.

## Текущие маршруты

- `site/index.html` — выбор интерфейса;
- `site/desktop/index.html` — настольная главная;
- `site/mobile/index.html` — мобильная главная;
- `site/desktop/page.html` — оболочка старой desktop-страницы;
- `site/mobile/page.html` — оболочка старой mobile-страницы;
- `site/shared/css/base.css` — базовые стили;
- `site/shared/js/navigation.js` — общая навигация и загрузка модулей.

## Правило для будущих изменений

Любое улучшение интерфейса оценивается по двум вопросам:

1. Сохраняются ли исходные технические данные без потерь?
2. Останется ли привычный рабочий сценарий понятным пользователю старого справочника?

Если новое оформление мешает одному из этих требований, оно должно быть упрощено либо вынесено в дополнительный слой.

## Следующие задачи интерфейса

1. Провести визуальную сверку набора типичных и сложных страниц с оригиналом.
2. Улучшить отображение различий между несколькими кандидатами схем после сопоставления с ESP32.
3. Не перегружать старую рабочую область новыми карточками: дополнительные данные ESP32 и CoilMaster держать в боковой панели либо отдельном компактном блоке.
4. После стабилизации read-only интеграции подготовить глубокие ссылки между внешним сайтом и карточками проекта ESP32.
