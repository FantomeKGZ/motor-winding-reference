# Клиент ESP32 для внешнего справочника

Внешний сайт использует единый JS-клиент `site/shared/js/esp32-client.js`. Он отделяет интерфейс сайта от конкретного способа получения данных.

## Режимы

- `off` — соединение с ESP32 отключено;
- `mock` — используются тестовые данные `site/shared/data/esp32-mock.json`;
- `live` — выполняется HTTP GET к реальной ESP32.

Режим тестирования `?esp32test=1` автоматически использует `mock`.

## Предлагаемый read-only endpoint ESP32

Первая версия интеграции ожидает:

```text
GET {baseUrl}/api/context
Accept: application/json
```

Этот endpoint пока является контрактом для будущей доработки прошивки ESP32. Внешний сайт не предполагает, что он уже существует.

Минимальный ответ:

```json
{
  "api_version": "1.0",
  "project_id": "P-000123",
  "motor": {
    "model": "АИР112М4",
    "slots": 36,
    "rpm": 1500,
    "phases": 3,
    "poles": 4,
    "connection": "Y",
    "winding_type": null,
    "parallel_branches": null
  }
}
```

Неизвестные значения передаются как `null`, а не вычисляются внешним сайтом.

## Настройка live-режима

Клиент не содержит жёстко заданного IP ESP32. Адрес задаётся отдельно, чтобы справочник работал в разных сетях.

Для временной проверки можно использовать параметры URL:

```text
?esp32=live&esp32url=http://192.168.1.50
```

Тогда запрос будет направлен на:

```text
http://192.168.1.50/api/context
```

Настройки также могут сохраняться через `window.CoilMasterEsp32Client.configure(...)` в `localStorage`.

## Таймаут и отказоустойчивость

По умолчанию HTTP-запрос прерывается примерно через 3.5 секунды. Ошибка ESP32 не должна блокировать обычный справочник: таблицы, поиск, изображения и старые страницы продолжают работать автономно.

## События

После успешного получения данных публикуется событие:

```text
coilmaster:esp32-context
```

Последний результат также доступен как:

```text
window.CoilMasterEsp32Context
```

## Безопасность

На текущем этапе клиент реализует только чтение. Команды записи, запуск оборудования, изменение склада или проекта через этот модуль не реализуются. Такие операции должны появляться только отдельным версионированным API с подтверждением пользователя.
