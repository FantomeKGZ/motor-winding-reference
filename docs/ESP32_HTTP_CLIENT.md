# Клиент ESP32 для внешнего справочника

Внешний сайт использует единый JS-клиент `site/shared/js/esp32-client.js`. Он отделяет интерфейс сайта от конкретного способа получения данных и позволяет разрабатывать интеграцию до готовности прошивки ESP32.

Актуальное состояние реализации также описано в `docs/CURRENT_STATUS.md`.

## Режимы

- `off` — соединение с ESP32 отключено;
- `mock` — используются тестовые данные `site/shared/data/esp32-mock.json`;
- `live` — выполняется HTTP GET к реальной ESP32.

Режим тестирования `?esp32test=1` автоматически использует `mock` для контрольной матрицы сопоставления.

## Предлагаемый read-only endpoint ESP32

Первая версия интеграции ожидает:

```text
GET {baseUrl}/api/context
Accept: application/json
```

Этот endpoint пока является контрактом для будущей доработки прошивки ESP32. Внешний сайт уже умеет обращаться к нему, но прошивка должна реализовать ответ отдельно.

Минимальный ответ:

```json
{
  "api_version": "1.0",
  "project_id": "P-000123",
  "motor": {
    "model": "АИР112М4",
    "slots": 36,
    "rpm": 1500,
    "phases": 3,
    "poles": 4,
    "connection": "Y",
    "winding_type": null,
    "parallel_branches": null
  }
}
```

Неизвестные значения передаются как `null`, а не вычисляются внешним сайтом.

## Настройка из интерфейса

В боковом меню уже реализована панель ESP32 (`site/shared/js/esp32-panel.js`). В ней пользователь может:

- выбрать `Выключено`, `Тест` или `ESP32`;
- указать базовый адрес устройства;
- сохранить настройки в `localStorage`;
- вручную проверить соединение;
- увидеть состояние связи;
- увидеть модель текущего двигателя, пазы, обороты и число фаз.

Пример базового адреса:

```text
http://192.168.1.50
```

В live-режиме клиент сам добавляет `/api/context`.

## Настройка через URL

Для временной проверки по-прежнему можно использовать:

```text
?esp32=live&esp32url=http://192.168.1.50
```

Тогда запрос будет направлен на:

```text
http://192.168.1.50/api/context
```

Настройки также доступны программно через:

```text
window.CoilMasterEsp32Client.configure(...)
```

## Таймаут и отказоустойчивость

По умолчанию HTTP-запрос прерывается примерно через 3.5 секунды.

Ошибка ESP32 не должна блокировать обычный справочник. При отсутствии связи продолжают работать:

- оригинальная таблица;
- старые HTML-страницы;
- изображения;
- быстрый поиск;
- полнотекстовый поиск;
- избранное;
- история просмотра.

## Mixed content

Если внешний сайт открыт по HTTPS, а ESP32 отвечает только по `http://`, браузер может заблокировать запрос как mixed content.

Панель ESP32 показывает предупреждение о такой конфигурации. Перед финальным развёртыванием live-интеграции нужно выбрать совместимый способ доступа к локальной ESP32: одинаковую схему HTTP/HTTPS, локальный прокси/шлюз либо другой согласованный вариант.

## События и глобальные объекты

После успешного получения данных публикуется событие:

```text
coilmaster:esp32-context
```

Последний результат доступен как:

```text
window.CoilMasterEsp32Context
```

Клиент доступен как:

```text
window.CoilMasterEsp32Client
```

и предоставляет как минимум:

- `getSettings()`;
- `configure(...)`;
- `getContext(...)`.

## Автоматическое сопоставление со справочником

После события `coilmaster:esp32-context` модуль `site/shared/js/esp32-scheme-matcher.js` автоматически использует данные двигателя.

Текущая версия:

1. читает реальные ссылки из уже загруженной оригинальной таблицы;
2. извлекает число пазов из строки;
3. извлекает обороты из текста ссылки;
4. ищет точное совпадение по `slots + rpm`;
5. подсвечивает найденную строку и ячейку;
6. прокручивает таблицу к найденной группе;
7. показывает список подходящих страниц.

Конкретная схема укладки автоматически не выбирается. Даже если найдена одна группа, мастер должен проверить параметры обмотки на самой странице.

## Mock-тесты

`site/shared/data/esp32-mock.json` содержит контрольную матрицу:

- `24 / 3000` — ожидается минимум одно совпадение;
- `36 / 1500` — ожидается минимум одно совпадение;
- `48 / 1000` — ожидается минимум одно совпадение;
- `37 / 777` — ожидается ноль совпадений.

Режим `?esp32test=1` используется для проверки алгоритма без физической ESP32.

## Что требуется добавить на стороне ESP32

Минимум для первого реального подключения:

1. реализовать `GET /api/context`;
2. возвращать UTF-8 JSON;
3. добавить версию API;
4. отдавать `motor.slots`, `motor.rpm`, `motor.phases` и по возможности `motor.poles`;
5. неизвестные поля возвращать как `null` либо не включать в ответ согласно окончательно утверждённой версии контракта;
6. не выполнять тяжёлый поиск и не передавать изображения справочника.

В дальнейшем желательно добавить поля:

- `winding_type`;
- `parallel_branches`;
- `connection`;
- специальные признаки многоскоростной/нестандартной обмотки.

Они позволят внешнему сайту сужать список схем после первичного поиска по пазам и скорости.

## Безопасность

На текущем этапе клиент реализует только чтение.

Не реализуются через этот модуль:

- команды запуска оборудования;
- изменение проекта;
- изменение склада;
- запись выбранной схемы;
- любые управляющие команды ESP32.

Такие операции должны появляться только после стабилизации read-only интеграции как отдельный версионированный API с проверкой входных данных и явным подтверждением пользователя.
