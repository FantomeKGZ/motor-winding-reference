# Текущее состояние проекта CoilMaster Handbook

Дата фиксации: 2026-08-07.

Этот документ описывает фактически реализованное состояние внешнего сайта справочника в ветке `feature/site-shell`. Он нужен как единая точка входа, чтобы не восстанавливать историю проекта по отдельным коммитам и сообщениям.

## 1. Границы проекта

Этот репозиторий содержит внешний сайт справочника и интеграционный слой для CoilMaster/ESP32. Прошивка ESP32 и её встроенный веб-сайт остаются отдельным проектом.

Эталонные архивные исходники находятся в:

- `sourse/desktop/Справочник от 09.12.2024 HTML`;
- `sourse/mobile/Справочник от 09.12.2024 для мобильных устройств HTML`.

Они не редактируются. Новая оболочка, инструменты и документация находятся в `site/`, `tools/` и `docs/`.

## 2. Что уже реализовано в интерфейсе

### Главные страницы

Созданы отдельные рабочие оболочки:

- `site/desktop/index.html`;
- `site/mobile/index.html`;
- `site/index.html` для выбора интерфейса.

Стартовая страница умеет рекомендовать desktop/mobile по ширине экрана, запоминать выбор в `localStorage` и позволяет вручную вернуться к выбору интерфейса.

Главная рабочая область не содержит заново набранной таблицы. `home-content-loader.js` загружает оригинальный `index.html` соответствующей версии, декодирует Windows-1251 и показывает исходный контент внутри новой оболочки.

Старый верхний графический баннер на рабочих страницах убран, но таблицы, значения, тексты и ссылки исходного справочника сохраняются.

### Совместимость со старым интерфейсом

Сохранены:

- исходная таблица выбора схем;
- числа пазов и оборотов;
- исходные ссылки;
- технический текст;
- изображения;
- порядок материалов;
- desktop и mobile как отдельные варианты.

Новая оболочка добавляет боковое меню, строку поиска и дополнительные функции вокруг старого содержимого, а не заменяет его.

### Открытие старых страниц в новой оболочке

Созданы:

- `site/desktop/page.html`;
- `site/mobile/page.html`;
- `site/shared/js/legacy-page-loader.js`.

Старые страницы загружаются из `sourse/`, декодируются из Windows-1251 и показываются внутри новой оболочки. Локальные HTML-ссылки переписываются на `page.html?src=...`, а изображения и другие ресурсы продолжают использовать оригинальные файлы.

На странице материала есть:

- `← Назад`;
- `К таблице схем`;
- `Оригинальная страница` для проверки исходника;
- кнопка `Наверх` после длинной прокрутки.

При возврате к главной таблице восстанавливается прежняя позиция прокрутки.

## 3. Поиск и навигация

### Быстрый поиск по главной таблице

`site/shared/js/navigation.js` поддерживает поиск непосредственно по оригинальной таблице.

Запрос вида `24 3000`:

- фильтрует строки;
- подсвечивает подходящую строку;
- подсвечивает точную ячейку;
- прокручивает к первому совпадению;
- показывает количество найденных совпадений.

### Полнотекстовый поиск

Создан `tools/build_search_index.py`, который строит отдельные поисковые индексы для desktop и mobile из старых HTML-файлов.

Интерфейс поиска реализован в `site/shared/js/fulltext-search.js`.

Он умеет искать по всему тексту справочника, а не только по главной таблице, и показывает:

- заголовок;
- фрагмент текста;
- путь страницы;
- тип материала.

Добавлены категории:

- схема укладки;
- схема соединения;
- данные двигателя;
- таблица;
- справочный материал;
- обычная страница.

Есть фильтры результатов `Все / Схемы укладки / Схемы соединения / Двигатели / Таблицы / Справочные`.

## 4. Удобство ежедневной работы

### Недавние страницы

`site/shared/js/recent-history.js` сохраняет до 8 последних открытых страниц в `localStorage` и показывает их в боковом меню.

Повторное открытие не создаёт дубликат, а поднимает страницу вверх списка. Историю можно очистить.

### Избранное

`site/shared/js/favorites.js` добавляет кнопку `☆ В избранное / ★ В избранном` на страницах справочника.

Избранные страницы хранятся локально и показываются отдельным разделом бокового меню.

## 5. Параметры схемы и интеграционный контекст

`site/shared/js/page-parameters.js` пытается безопасно извлечь из существующих таблиц страницы основные параметры:

- число пазов;
- обороты;
- `2p`;
- `q`;
- начало фаз.

Если найдено достаточно данных, сверху показывается компактный блок `Параметры схемы`. Исходная таблица при этом остаётся без изменений.

Дополнительно создаётся объект:

`window.CoilMasterSchemeContext`

и событие:

`coilmaster:scheme-context`.

Подробный контракт описан в `docs/SCHEME_CONTEXT_CONTRACT.md`.

Ключевое правило: отсутствующие значения не угадываются и становятся `null`.

## 6. Инвентаризация и защита исходных данных

### Ссылки

`tools/build_scheme_index.py` проверил главные страницы:

- desktop: 350 локальных HTML-ссылок;
- mobile: 349;
- общих целей: 349;
- битых ссылок: 0;
- `y63500.html` присутствует только в desktop.

### HTML-страницы

`tools/build_page_inventory.py` проанализировал:

- 1856 HTML-страниц desktop;
- 1856 HTML-страниц mobile;
- всего 3712 страниц.

Зафиксировано правило: технический текст, подписи, формулы, таблицы, ссылки и специфичные элементы страниц автоматически не удаляются.

### Изображения

`tools/build_image_inventory.py` проанализировал:

- 5522 изображения desktop;
- 5522 изображения mobile;
- 11044 файлов всего;
- 5521 уникальное байтовое содержимое по SHA-256.

Почти весь набор desktop имеет побайтно идентичную копию в mobile, но это не является разрешением на автоматическое удаление.

Главное правило проекта: изображения не объединяются и не удаляются автоматически. Даже точный SHA-256 дубликат сначала рассматривается в контексте страницы.

Workflow `.github/workflows/validate-handbook-links.yml` автоматически запускает анализ и создаёт производные отчёты:

Исходные файлы при этом не меняются.

## 8. Интеграция с ESP32

### Общий принцип

Схема не привязывается жёстко к `motor_id`. Связь строится так:

`данные ESP32 → параметры двигателя/обмотки → поиск группы во внешнем справочнике → ручной выбор конкретной схемы при неоднозначности`.

ESP32 не должна хранить тяжёлые изображения справочника и выполнять полнотекстовый поиск.

### JS-клиент ESP32

Создан `site/shared/js/esp32-client.js`.

Он поддерживает режимы:

- `off` — ESP32 отключена;
- `mock` — тестовые данные из локального JSON;
- `live` — реальный HTTP GET к ESP32.

Предлагаемый endpoint:

`GET {baseUrl}/api/context`

Клиент:

- не содержит жёстко заданного IP;
- хранит настройки локально;
- имеет таймаут около 3.5 секунд;
- не блокирует справочник при недоступности ESP32;
- реализует только чтение.

После успешного чтения публикуется событие `coilmaster:esp32-context` и сохраняется `window.CoilMasterEsp32Context`.

### Панель ESP32

`site/shared/js/esp32-panel.js` добавляет в боковое меню панель ESP32.

В ней реализованы:

- индикатор состояния;
- выбор `Выключено / Тест / ESP32`;
- поле адреса ESP32;
- сохранение настроек;
- кнопка `Проверить соединение`;
- отображение текущего двигателя;
- сообщение об ошибке связи;
- предупреждение о возможной блокировке HTTP-запроса браузером, если внешний сайт открыт по HTTPS.

### Сопоставление ESP32 со справочником

`site/shared/js/esp32-scheme-matcher.js` после получения контекста двигателя:

- читает реальные ссылки из уже загруженной оригинальной таблицы;
- определяет число пазов из строки;
- определяет обороты из ссылки;
- ищет точное совпадение по `slots + rpm`;
- подсвечивает подходящую строку и ячейку;
- прокручивает к найденной группе;
- показывает блок `ESP32 → подходящие схемы` со списком кандидатов.

Конкретный вариант укладки автоматически не выбирается.

### Тестовый режим сопоставления

В `site/shared/data/esp32-mock.json` есть контрольная матрица:

- 24 / 3000 — должно быть совпадение;
- 36 / 1500 — должно быть совпадение;
- 48 / 1000 — должно быть совпадение;
- 37 / 777 — совпадений быть не должно.

Режим `?esp32test=1` показывает результат этих проверок отдельно от live-интеграции.

## 9. Что пока не реализовано

На текущем этапе ещё не завершены:

- реальный endpoint `/api/context` в прошивке ESP32;
- чтение склада проводов с ESP32;
- чтение истории работ и журнала событий;
- расширенная фильтрация схем по `winding_type`, `parallel_branches`, `connection` и другим признакам;
- стабильный `scheme_id` для каждой самостоятельной схемы;
- сохранение выбранной схемы обратно в проект ESP32;
- команды записи в ESP32;
- любые команды управления оборудованием;
- окончательная оптимизация и дедупликация файлов;
- финальная проверка всех страниц desktop/mobile визуально рядом с оригиналом.

## 10. Ближайший технический этап

Следующая логичная задача — перейти от грубого совпадения `slots + rpm` к многоступенчатому сопоставлению:

1. сначала найти группу по пазам и оборотам/полюсности;
2. затем отфильтровать кандидатов по типу обмотки;
3. затем по параллельным ветвям;
4. затем по типу соединения и специальным признакам;
5. при остатке нескольких вариантов показать мастеру различия, не выбирая схему автоматически.

Параллельно необходимо подготовить в проекте ESP32 read-only endpoint `/api/context` по контракту из `ESP32_INTEGRATION_REQUIREMENTS.md` и `docs/ESP32_HTTP_CLIENT.md`.
