# Требования к интеграции с ESP32

Этот файл является техническим заданием для проекта CoilMaster/ESP32. Реализация прошивки ESP32 выполняется в отдельном репозитории.

## Цель

Внешний сайт должен уметь показывать рабочие данные, которые уже хранятся на ESP32, без их постоянного дублирования на внешнем сайте.

## Минимальные данные, которые ESP32 должна уметь отдавать

- состояние системы;
- сведения о текущем проекте/намотке;
- обмоточные данные выбранного двигателя;
- параметры, необходимые для поиска подходящей схемы во внешнем справочнике;
- склад проводов и остатки;
- историю выполненных работ;
- журнал ошибок и событий;
- версию API/формата данных.

## Параметры для сопоставления со схемой

Схема укладки не считается частью конкретного двигателя. ESP32 передаёт только параметры, достаточные для поиска схемы, например:

- число пазов;
- число полюсов или номинальные обороты;
- число фаз;
- тип обмотки;
- число параллельных ветвей, если оно влияет на выбор;
- тип соединения, если он известен;
- дополнительные признаки нестандартной схемы.

Внешний сайт выполняет поиск по собственному справочнику и показывает изображения и описание схемы.

## Нагрузка на ESP32

ESP32 не должна:

- выполнять полнотекстовый поиск по справочнику;
- хранить тяжёлые изображения внешнего справочника;
- преобразовывать или индексировать сотни HTML-страниц;
- дублировать справочную базу внешнего сайта.

ESP32 должна отдавать небольшие структурированные ответы и принимать только явно определённые команды.

## Формат обмена

Предпочтительный формат — UTF‑8 JSON через HTTP API в локальной сети. Все числовые единицы должны быть однозначно задокументированы.

Пример ответа:

```json
{
  "api_version": "1.0",
  "project_id": "P-000123",
  "motor": {
    "model": "АИР112М4",
    "slots": 36,
    "rpm": 1500,
    "phases": 3,
    "connection": "Y"
  }
}
```

## Безопасность команд

На первом этапе внешний сайт должен работать преимущественно в режиме чтения. Команды, которые изменяют данные на ESP32 или могут запустить оборудование, должны быть отдельными, явно подтверждаемыми и версионированными.
